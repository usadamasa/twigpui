# code-metrics-ratchet

`scripts/code-metrics.sh` がファイルサイズ・関数長・認知的複雑度を出す。
CI の Lint ジョブが毎回走らせて run summary に貼る。

**このうち CI を落とすのはファイルサイズだけ。** 残りは報告のみ。

## ファイルサイズの天井

`scripts/code-metrics.sh --check` が `metrics-baseline.tsv` の天井 (実装行数を
50 行単位で切り上げた値) と突き合わせる。超えたら CI が落ちる。

落ちたときの選択肢は 2 つだけ。

1. **ファイルを分割する。**
2. **同じ PR で天井を上げ、理由を書く。**

天井を上げるのは正当な操作。目的は「黙って育てられないこと」であって、
成長を禁じることではない。同じ PR に含まれるので、レビューする人の目に必ず入る。

**ファイルが縮んだら天井も下げる。** 下げないと、次に太ったときに気づけない。

## 新規ファイル

**`metrics-baseline.tsv` に先に登録しないと CI が落ちる。**
`.rs` を新しく足したら、同じ PR でベースラインにも行を足す。

## 関数長と複雑度

- 関数長は `clippy::too_many_lines` が `pedantic` 経由で deny になっていて既に見ている。
  code-metrics 側の報告は重複なので、CI を落とす役は持たせていない。
- 認知的複雑度は clippy の既定閾値で 1 件も出ないため、報告のみ。

## 計測ツールを足すとき

CI で毎回かかるインストール時間に見合うかを先に確かめる。
ビルド時間はこのリポジトリで実際に効いてくるコストなので、
「あると便利」だけでツールを増やさない。
