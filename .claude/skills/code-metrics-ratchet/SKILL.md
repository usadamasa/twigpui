# code-metrics-ratchet

`scripts/code-metrics.sh` がファイルサイズ・関数長・認知的複雑度を出す。
CI の Lint ジョブが毎回走らせて run summary に貼る。

**このうち CI を落とすのはファイルサイズだけ。** 残りは報告のみ。

## ファイルサイズの上限

`scripts/code-metrics.sh --check` が各ファイルの実装行数 (`#[cfg(test)]` より前) を
一律の上限 `max_implementation_lines` (600 行) と突き合わせる。超えたら CI が落ちる。

落ちたときの道は 1 つ。**ファイルを分割する。**

- 同じモジュール木の子ファイルへ `impl` ブロックごと出す。兄弟から呼ぶものは
  `pub(super)`、孫 (`ui/tasks/*.rs` のような 1 段深い場所) から `ui` の兄弟へ
  見せるものは `pub(in crate::ui)`。`pub(crate)` へは広げない。
- テストは対象の関数と一緒に動かす。新しいファイルの `#[cfg(test)]` は 0 桁目に置く
  (そこが実装とテストの境界)。
- 切る前に、分けた先がそれぞれ上限に収まる行数か数える。

新しいファイルの登録は要らない。上限は全ファイルに効く。

## `metrics-baseline.tsv`

上限より大きいまま残っているファイルと、その天井の一覧。**縮むことしかできない。**

- 行を足せない。上限を超えた新しいファイルは分割する。
- 天井を `origin/main` の値より上げられない。
- ファイルが上限を下回ったら、同じ PR で行を消す。残っていると落ちる。
- ファイルが消えたら行も消す。

このファイルに理由の散文は書かない。理由は PR に書く。

## 上限そのものを動かすとき

`scripts/code-metrics.sh` の `max_implementation_lines` を変えて、理由を PR に書く。
全ファイルに効く 1 か所の変更なので、diff で見落としようがない。
ファイルごとの例外を作る道は無い (#241 でそれを閉じた)。

## 関数長と複雑度

- 関数長は `clippy::too_many_lines` が `pedantic` 経由で deny になっていて既に見ている。
  code-metrics 側の報告は重複なので、CI を落とす役は持たせていない。
- 認知的複雑度は clippy の既定閾値で 1 件も出ないため、報告のみ。

## 計測ツールを足すとき

CI で毎回かかるインストール時間に見合うかを先に確かめる。
ビルド時間はこのリポジトリで実際に効いてくるコストなので、
「あると便利」だけでツールを増やさない。
